# Cloudflare Worker setup

The Cloudflare Worker provides the CORS-capable Decky custom-store
endpoint at:

```text
https://homebrew.imsilverfoxy.com/plugins.json
```

The Worker proxies the catalog generated by the existing GitHub Pages
release workflow. Release ZIPs and the source catalog remain on GitHub Pages.

## Dashboard configuration

1. In Cloudflare, open **Workers & Pages** and choose **Create application**.
2. Choose **Import a repository** and select the `decktation` repository.
3. Configure the production branch as `master`.
4. Use these build settings:
   - Build command: `npm test`
   - Deploy command: `npx wrangler deploy`
   - Root directory: `cloudflare`
5. Save and deploy. Verify the generated `*.workers.dev/plugins.json` URL before
   configuring DNS.
6. In the Worker, open **Settings > Domains & Routes**, choose
   **Add > Custom Domain**,
   and enter `homebrew.imsilverfoxy.com`.
7. If `imsilverfoxy.com` is already managed by the same Cloudflare account,
   allow Cloudflare to create the DNS record. Otherwise, create the CNAME that
   Cloudflare displays after associating the domain with the Pages project.

## Verification

Replace `<worker-host>` with the assigned `*.workers.dev` hostname for the first
test, and then repeat with `homebrew.imsilverfoxy.com`:

```sh
curl -i -X OPTIONS \
  -H 'Origin: https://steamloopback.host' \
  -H 'Access-Control-Request-Method: GET' \
  -H 'Access-Control-Request-Headers: X-Decky-Version' \
  https://<worker-host>/plugins.json

curl -i \
  -H 'Origin: https://steamloopback.host' \
  -H 'X-Decky-Version: test' \
  https://<worker-host>/plugins.json
```

The preflight must return `204` with all three `Access-Control-Allow-*`
headers. The GET must return `200`, the same CORS headers, and the catalog JSON.
